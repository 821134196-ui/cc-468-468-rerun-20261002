# 社区地下车库防汛挡板部署与归位系统

管理车库入口、挡板分段、立柱、密封条、存放架、预警等级、部署任务、现场人员、安装照片、
积水观察、拆除清洗与缺件补充的全流程演示系统。人员与天气均为演示数据，**仅依赖 Python 3
标准库 + 浏览器原生 JS，无任何第三方依赖**。

## 一条本地启动命令

```bash
./start.sh              # 默认 http://localhost:8000
PORT=8211 ./start.sh    # 自定义端口
```

启动时会重置 SQLite 并载入三类样例：**在途部署**（东门装到槽1）、**归架缺件**
（西门差一条密封条待主管审批补充）、**提前解除待审批**（北门已部署封控，预警仍在）。
天气时间轴默认 2 倍速、从“雨势增强”阶段开始，约 10 秒后水位越过橙色阈值，可观察到
自动升级与按入口自动生成部署清单；约 45 秒后回落，连续两次复查自动解除预警。

停止：`Ctrl+C`。

运行测试：

```bash
python3 -m unittest discover -s tests -v
```

## 核心业务规则

| 场景 | 规则 |
|---|---|
| 预警达阈值 | 监控任务按雨量/各入口水位判定蓝黄橙红；橙色及以上按入口**自动生成部署清单**（在途任务不重复生成） |
| 领件排他 | 挡板/立柱/密封条以条件更新原子锁定（`status='available'` 才可锁）；**同一器材不能被两个入口同时领取** |
| 挡板错段 | 扫码编号必须与该槽锁定件一致，错段即拦截并开异常单；两槽扫反可交换纠正，另一槽确认标记作废需重装重验 |
| 密封条破损 | 安装中或归架发现破损：旧件转破损、自动开报损单，从库存换件继续 |
| 分段完整 | 每槽挡板/密封条就位、立柱就位，逐段**连接确认 + 密封确认**全部完成才允许结束安装 |
| 通道封控 | 保安/主管执行；未封控不能完成部署；临时车辆放行期间自动解封且不得重新封控，车辆通过后恢复 |
| 人员迟到 | 晚于约定到场自动登记迟到异常 |
| 入口积水 | 人工观察水位 ≥ 橙色阈值开积水异常，**未复查关闭禁止拆除** |
| 拆除时机 | 预警未解除拆除即“拆除过早”并制止；须提交提前解除申请、**物业主管批准**后方可拆；保安无权审批 |
| 清洗晾干 | 拆除 → 清洗 → 晾干 → 归架核对，器材状态随阶段流转 |
| 归架差异 | 逐件核对完好/破损/缺件；差异自动生成补充单，主管审批、补充入库后闭环 |
| 重新可用 | 全部逐件核对且差异闭环后，条件更新完成任务（**并发完成只生效一次**），器材解除占用回到可用库存 |

### 角色权限

- **保安（周建国）**：通道封控/解封、临时车辆放行、异常复查关闭、到场登记
- **安装工（李海涛/王大山）**：领件、安装、逐段确认、清洗归架、提前解除**申请**
- **物业主管（陈立群）**：全部安装权限 + 提前拆除**审批** + 缺件/报损**审批**

## 页面（六个视图）

1. **预警看板**：等级横幅、统计卡、简洁雨量线形图（SVG，带阈值线与悬停提示，
   只占独立卡片，不覆盖任务信息）、在途任务、未闭异常
2. **入口示意图**：按挡板**实际拼接顺序**横向排列 `立柱—槽—立柱—…—立柱`，
   已装/已领未装/缺段空槽（橙色虚线空槽）、密封条状态一眼可辨
3. **器材领用**：部署清单逐件锁定（整单领取/单件领取/指定编号），实时库存与占用入口
4. **分段安装（移动端优先）**：每段一张卡片，**大勾选区**确认连接/密封，
   扫码入槽、错段纠正、密封条更换；底部**固定橙色拍照入口**，调用手机相机
5. **积水观察**：各入口水位仪表、人工观察上报（超阈值自动开积水异常）、
   人员到场登记、演示天气手动控制
6. **拆除·清洗·归架**：五步流程条、提前拆除申请/主管审批、拆除清洗晾干按钮、
   逐件完好/破损/缺件核对、补充单审批与入库

配色：混凝土浅灰底色、雨水蓝主色、警戒橙行动色、红/黄/蓝预警状态色
（状态色均带文字标签，不只靠颜色区分）。

## 数据与存储

- `data/flood.db`：SQLite（WAL 模式），表包括 personnel / entrances / equipment /
  alerts / tasks / task_items / photos / water_observations / rainfall_readings /
  level_readings / incidents / temp_passes / task_personnel / supply_requests
- `photos/`：现场照片原始文件（base64 上传落盘），数据库只存路径
- 进程内守护线程每 3 秒从模拟天气适配器取一次雨量与各入口水位，写入读数并推动
  预警升级、自动生成清单、回落复查解除

## 目录结构

```
start.sh              一条启动命令（重置+样例+启动）
run.py                入口：DB、监控线程、HTTP 服务
app/db.py             SQLite schema
app/service.py        领域服务（锁定/状态机/审批/归架）
app/weather.py        模拟天气适配器（确定性暴雨过程线，可手动覆写）
app/monitor.py        进程内监控任务（升级/清单/复查解除）
app/seed.py           演示数据与三类样例场景
app/server.py         stdlib HTTP：JSON API + 静态页 + 照片落盘
web/                  index.html / styles.css / app.js（原生 JS SPA）
tests/                19 项测试：排他、错段、分段完整、角色、预警状态、
                      提前审批、积水拦截、归架差异、并发一次、监控、HTTP
```
